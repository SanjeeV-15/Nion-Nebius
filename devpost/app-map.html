Nion — app map

A one-page guide to how Nion is built, so you know where things live and where to start when you want to change something. It is a snapshot of the code at commit 77cd897; the code may move on, so check names against the source.

What it is

Nion is a hands-free voice companion, designed for ears and not screens. You say "Hey Nion", ask something out loud, and it answers out loud: short, honest about what it knows, with its sources named. It has four main pieces.

The pagepublic/ runs in Chrome. It hears you, decides what you meant, speaks, shows the icon, and keeps History.
The serverserver/ is a small Node program. It holds your API key and asks Claude. The page never sees the key.
ClaudeThe brain. It writes the answer and can search the web, guided by the rules in server/prompt.js.
The teststests/ checks each behavior without a microphone or a key. scripts/ holds the paid checks.

One action, start to finish

You say "Hey Neon, what's the time in Denver?". This is the path it takes through the code.

Everything you saw on screen comes from these steps: the icon changes at each state, and History shows what was saved.

A route through the code

A reference route. Search for the names in quotes, since line numbers drift.

Stop 1 · public/js/wake.js — "parseUtterance"
Recognises "Hey Nion". Chrome often writes the name as "Indian", "anyone" or "any on", so MISHEARD_WAKE accepts those, but only at the start of a sentence and only when a request word follows. That keeps "Indian food near me" from waking Nion. It also holds the spoken commands (START_CONVERSATION, END_CONVERSATION).
Stop 2 · public/js/app.js — "ask"
The controller. ask sets the icon to thinking, adds your question to the conversation, and sends it to /api/chat. It has a 25 second give-up timer (ASK_TIMEOUT_MS), a "one moment" timer (FILLER_AFTER_MS), the spoken failure message (TROUBLE), and the call that saves the answer for History (recordExchange). decide, in conversation.js, chooses what to do with each thing heard; this file carries it out.
Stop 3 · server/prompt.js — "RULES"
Nion's personality, in plain English: under about 60 words, at most five items, name sources aloud, say plainly when nothing is found, be honest about what it can't do yet. Most "Nion should act differently" changes are a sentence here. The Claude call itself is askNion in server/brain.js; web search helpers are in server/search.js.

A practice to reuse

When something breaks, give the agent evidence, then turn the fix into a test.

In this project the three biggest fixes each started with evidence and not a description. Opening the page with ?debug showed Chrome writing "Hey Nion" as "Indian", which led to MISHEARD_WAKE in wake.js and a test in tests/conversation.test.js. The same log showed Nion hearing its own voice ("I can answer question"), which led to public/js/echo.js and tests/echo.test.js. A server log line ("credit balance is too low") explained why every request failed, which led to server/failure.js.

The same idea works the other way, too. When you edited the goodbye, a test failed. The log said exactly what it expected and what it got, and showing that was enough to see the test had been too picky about Nion's last sentence. A failing test is evidence about either the code or the test, and the output tells you which.

On another project: before asking an agent to fix something, collect what actually happened (a log, an error, a failing test's output) and paste that in. When it's fixed, ask for a test that would have caught it.

Run it again

npm install
cp .env.example .env     # put your own Claude API key in .env
npm start                # then open http://localhost:3000 in Chrome
npm test                 # free: 100+ tests, no key needed
?debug                   # add to the address to see what Nion hears and decides

Paid checks, which spend your API credit: npm run check:replies and npm run check:speed. The full instructions are in README.md.
