Nion — technical spec

How the app is built: a Chrome page that listens and speaks, a small server that guards your key, and Claude as the brain.

In plain language

1. The pageRuns in Chrome. Hears you, speaks aloud, shows the state icon, and keeps your name and history in the browser.
2. A small serverRuns on your laptop. Holds your Claude API key so the page never sees it.
3. ClaudeThe brain. Answers in a short, spoken style and can search the web with sources.
4. Chrome speaksThe page reads the answer aloud, then goes back to listening.
One browser rule: you tap the icon once to start, because browsers won't open the microphone or speak without a tap. After that, everything is by voice.

Components

Main screen index.html · styles.css · ui.js
Wordmark, the state icon, a one-line status caption, and a quiet History link. The first tap on the icon turns Nion on; after that no taps are needed.
PRD: Screens and Layout, Voice conversation
Conversation controller app.js
The single place that decides: waiting, listening, thinking, speaking, and whether a conversation is active. It stops listening while Nion speaks, and resumes after.
PRD: Voice conversation, States and Boundaries
Hearing speech-in.js
Wraps Chrome's speech recognition. Listens continuously in English and restarts itself when the browser stops. Paused while Nion speaks.
PRD: Voice conversation
Wake phrase and commands wake.js · tests/wake.test.js
A small testable function: is this "Hey Nion ..."? What's the question after it? Is it "let's start a conversation" or "end the conversation"? Accepts several spellings, since Chrome may write "Neon" or "Nyan."
PRD: Voice conversation
Speaking speech-out.js
Wraps Chrome's speech synthesis. Picks the best English voice on the machine, speaks the reply, and reports when it's done.
PRD: Designed for ears, not screens
Location location.js
Asks the browser for location only when a question needs it. If denied or unavailable, Nion asks by voice: allow location, or say where you are. A spoken place is remembered for the conversation.
PRD: Where am I
The brain (server) server/index.js · brain.js · prompt.js
Builds the prompt and calls Claude with web search on. Nion's rules in the prompt: short spoken answers, no lists or links, at most five items then ask, one clarifying question for broad questions, understand rambling speech and say back in one sentence what it understood when a message is long, name news sources aloud, say so when nothing is found, summarize markets but never advise, opinion plus a follow-up on decisions, greet by name only when a conversation starts. A local question with no location returns a marker that the page turns into the spoken fallback.
PRD: Designed for ears, not screens, Questions Nion can answer, Current events and sources, A partner with a point of view
Name and conversations storage.js
Saves your name once and each conversation's turns in the browser, so History can show them.
PRD: History and transcripts, States and Boundaries
History screen history.html · history.js
Lists past conversations, newest first. Open one to see its transcript and copy it.
PRD: History and transcripts

Look and feel

  • Greys only, near-black to near-white; no accent colors
  • Frosted glass panels with a soft light border
  • System sans font; "NION" in small capitals, wide spacing
  • Four state icons told apart by shape and motion: ring, microphone, three dots, speaker waves

How to run it

  • npm install
  • Copy .env.example to .env and add your own Claude API key (never in chat or the repo)
  • npm start, then open http://localhost:3000 in Chrome, tap once, allow the microphone
  • Record the laptop screen with earphones in for the demo. A hosted phone version is an optional stretch.

Where it will break, and what happens

  • Wake phrase not recognized → several spellings accepted; tapping the icon is the backup
  • Claude or search slow or failing → icon stays in "thinking," then Nion says it's having trouble reaching its sources
  • Location denied → asks by voice: allow it, or say where you are
  • Safari or Firefox → a screen says to use Chrome
  • No API key → server stops at startup and names .env

What was simplified

  • Browser speech instead of a paid voice service (one outside service only)
  • One tap to start (browser rule)
  • Wake phrase by text matching, not a wake-word engine
  • No interrupting mid-sentence
  • Browser storage instead of a database
  • No streaming of the reply
  • Chrome only; laptop first
